# Contributing to ARSY CODE

By participating, you agree to follow our [Code of Conduct](CODE_OF_CONDUCT.md).

## Propose a change

- Small fixes may go directly to a pull request.
- Open an issue before changing architecture, public protocols, policy, or the roadmap.
- Branch from `main` with `<type>/<short-description>`, for example `fix/resume-error` or `docs/config-schema`.

## Commits and pull requests

Use [Conventional Commits](https://www.conventionalcommits.org/) with an imperative subject, such as `fix: reject stale edits`. Keep one task per commit and each commit buildable and testable.

Pull requests must explain the change and list the checks actually run. The [maintainers](https://github.com/orgs/suiflex/teams/maintainers) review correctness, scope, tests, security boundaries, compatibility, and documentation. Resolve review comments and obtain maintainer approval before merge; authors do not approve their own changes.

Architectural decisions follow the [ADR process](docs/ADR/README.md).
